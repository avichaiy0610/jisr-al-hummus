# ג׳יסר א־חומוס 🧆

כפר דמיוני וסאטירי על החוף. כל מי שעוקב אחרי הכפר באינסטגרם מקבל בית עם מספר קבוע.
האתר סטטי לגמרי ורץ בחינם על GitHub Pages, בלי שרת ובלי שירותים בתשלום.

## איך זה עובד

```
ייצוא עוקבים מאינסטגרם  →  npm run update -- <קובץ>  →  git push  →  GitHub Pages
```

- **`data/registry.json`:** ספר הבתים, וזה מקור האמת. התושב במקום k גר בבית מספר k+1, והמספר לא זז לעולם.
- **עוקב שעזב:** הבית שלו נשאר פנוי ונצבע אפור. השם שלו נמחק, ונשמר רק "טביעת אצבע" (hash).
- **עוקב שחוזר:** מקבל בחזרה את אותו בית.
- **`site/data/`:** הקבצים שהאתר קורא. הם נוצרים אוטומטית, ולא עורכים אותם ידנית.
- **קובץ הייצוא הגולמי:** לא נכנס לגיט. התיקייה `exports/` מוחרגת, כי הקובץ יכול להכיל מידע פרטי נוסף.

## הקמה (פעם אחת)

אני (Claude) לא פותח חשבונות בשמך. את השלבים האלה עושים בעצמך:

1. פותחים חשבון ב־[github.com](https://github.com), אם עוד אין.
2. יוצרים ריפו חדש וריק (Public), למשל `jisr`.
3. בתיקיית הפרויקט מריצים:
   ```
   git remote add origin https://github.com/<שם-המשתמש>/jisr.git
   git push -u origin main
   ```
4. בריפו נכנסים ל־**Settings → Pages**, ותחת **Source** בוחרים **GitHub Actions**.
5. אחרי דקה־שתיים האתר עולה בכתובת `https://<שם-המשתמש>.github.io/jisr/`.
6. כשעמוד האינסטגרם קיים, כותבים את שם המשתמש שלו ב־`INSTAGRAM_HANDLE` שבקובץ `site/js/copy.js`.

## עדכון התושבים (כל כמה ימים)

1. באינסטגרם: **הגדרות → מרכז החשבונות → המידע שלך והרשאות → הורדת המידע שלך**.
   - בוחרים את החשבון של הכפר.
   - בוחרים **חלק מהמידע**, ומסמנים רק את **Followers and following**.
   - פורמט **JSON**. טווח תאריכים **כל הזמנים**.
2. כשהקובץ מוכן מורידים את ה־zip. לא צריך לפתוח אותו.
3. מריצים:
   ```
   npm run update -- "C:\path\to\instagram-export.zip" --push
   ```
   בלי `--push` הנתונים מתעדכנים רק במחשב, ואז מריצים `git add -A`, `git commit` ו־`git push` ידנית.
4. הסקריפט מדפיס כמה בתים חדשים נוספו, כמה עוקבים עזבו וכמה חזרו.

**הגנה:** אם בקובץ יש פחות מחצי מהתושבים הנוכחיים, הסקריפט עוצר, כי כנראה הורד קובץ חלקי. אם זה באמת נכון, מוסיפים `--force`.

## פקודות

| פקודה | מה עושה |
|---|---|
| `npm install` | פעם אחת, אחרי הורדת הפרויקט |
| `npm start` | שרת מקומי בכתובת http://localhost:8080 |
| `npm run demo` | יוצר 30,000 תושבים מומצאים. צופים בהם בכתובת http://localhost:8080/?demo |
| `npm test` | בדיקות |
| `npm run update -- <קובץ> [--force] [--push]` | עדכון התושבים מקובץ הייצוא |
| `npm run vendor` | מעתיק את Three.js לתיקייה `site/vendor`, אחרי שדרוג גרסה |

## מבנה

- **`site/`:** האתר עצמו (HTML, CSS ו־ES modules), בלי שלב בנייה.
  - **`js/shared/`:** קוד שגם האתר וגם הכלים משתמשים בו: גיבוב SHA-256, ניקוי של שם משתמש ותוכנית הכפר.
  - **`js/village.js` ו־`js/landmarks.js`:** הכפר בתלת־ממד (Three.js).
  - **`js/copy.js`:** כל הטקסטים והבדיחות. אפשר לערוך בחופשיות.
- **`tools/`:** קריאת הייצוא, ניהול ספר הבתים וכתיבת קובצי הנתונים.
- **`tests/`:** בדיקות (`node --test`).

## אסור לשבור

- **תוכנית הכפר** (`site/js/shared/layout.js`) קפואה ונבדקת ב־checksum. אם משנים אותה אחרי שיש תושבים אמיתיים, בתים יזוזו ממקומם.
- **החלפת שם משתמש:** מי שמחליף שם משתמש באינסטגרם נחשב דייר חדש. אין דרך לדעת שזה אותו אדם.
- **פרטיות:** ספר התושבים ציבורי. זה כתוב גם באתר, בלשונית "עוד".
